# Gen Plan — 生成简洁可执行计划

**目标**：把需求压成一条核心路径——≤5 步，每步一行，直接可执行。
**铁律**：每一步都套用 `/keep-it-short` 规则精简；计划不是文档，是行动路径。

## 执行流程

1. 用 Skill 工具加载 `keep-it-short`，随后按它的规则精简每一步。
   - 若 Skill 工具不可用，内联执行其规则：每步 ≤1 句话、列表每项独立可读。
2. **先读关键文件，再出计划（必做）**：用 Read / Glob / Grep 定位并阅读需求涉及的关键代码与文件，据此准确理解用户意图（现状、范围、约束）；理解不了就问，**禁止仅凭猜测做决策**。
   - 意图不明确时，先向用户复述你的理解确认；不要跳过阅读直接产出。
3. 确认背景（仅当阅读后仍缺失时）：用 AskUserQuestion 问最关键的 1 个缺失项（目标 / 范围 / 验收标准），不要连环提问。
4. 生成计划（格式见下），输出在对话中，同时**写入项目根目录的 `draft.md`**（Write 整体覆盖，单一正本；与 context.md / handoff.md 同级）。

## 计划格式

- **目标**：一句话（≤20 字），说清"把 X 做到什么程度"。
- **主线**：步骤按依赖排序，前一步的输出是后一步的输入；顺序不顺时重排步骤，而不是加解释性文字。
- **步骤**：Markdown 待办清单——每步一行 `- [ ] 1. 做什么 → 怎么验证`，≤5 步；执行中由 `/step-by-step` 把完成的项改为 `- [x]`。
  - 每步一句"做什么"，半句"怎么验证"；核心思想（为什么这么做）只在必要时用括号半句补充。
  - 每步独立可读：跳读任一步都能单独理解（keep-it-short 第 3 条）。
- **层级**：最多两级；子项存在仅当拆分后每项仍一句话讲得清。
- **砍掉**：背景重述、方案对比、备选分支、技术细节展开、风险清单。必要信息合并成一行"注意"。

示例：

> **目标**：把 Qwen3-VL 训练脚本从单卡适配到 8 卡 FSDP2。
>
> - [ ] 1. 定位硬编码 device/batch 处 → 产出改动点清单
> - [ ] 2. 接入 FSDP2 初始化与 shard 配置 → 单卡 smoke 通过
> - [ ] 3. 8 卡 torchrun 跑 100 步 → loss 曲线与单卡对齐
>
> 注意：SP 等备选方案不在本期范围。

## draft.md（计划草稿文件）

- **位置**：项目根目录 `draft.md`，与 context.md / handoff.md 同级；目录下不存在时新建。
- **性质**：临时草稿——记录当前希望执行的步骤，用户与 agent 讨论迭代，用户可无负担随时改；执行中的计划变更也直接改它。
- **写入**：每次 /gen-plan 调用整体覆盖（单一正本），不追加历史版本。
- **收尾**：任务完成后可作为记录归档留档，本地文件保留。

## 自查（输出前）

1. 关键文件已读、用户意图已确认，计划没有任何一步是基于猜测的？
2. 每步能被单独读懂吗？互相依赖的步骤合并成一句了吗？
3. 步骤 ≤5 吗？层级 ≤2 吗？
4. 每步都有可验证落点（输出 / 命令 / 验收标准）吗？
5. 有没有只铺垫背景、不含动作的句子？有则删。

## 与其他 skill 的关系

- 计划落盘：gen-plan 把计划写入项目根目录 `draft.md`（执行计划草稿，用户可随时改）；任务完成后可作为记录归档留档。
- `/step-by-step`：计划生成后需要逐步确认执行时，配合它走"展示 → 确认 → 执行"循环。
