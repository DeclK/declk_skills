# Tech Note — 技术笔记整理规范

## 核心原则

当用户请你整理技术笔记时，遵守以下规则。这些规则来自于用户多次反馈中沉淀的偏好。

**使用方式：agent 只补全与用户已经讨论好的小节，内容精简，不做创作性展开、不写大段描述。**

## 规则

### 1. 保留原文，只处理 `/ai` 标记

原文绝对不动。agent 只处理 `/ai` 标记处：补全后删除标记及要求文本，原文其余部分保持原样。

### 2. 语言分工与代码块格式

- **代码块之外**（章节标题、段落描述、解释说明）→ 使用**中文**
- **代码块之内**（伪代码注释）→ 使用**英文**
- **代码块必须标注语言**：markdown 代码块必须以 ` ```python `、` ```cpp `（CUDA 也用 `cpp`）、` ```txt ` 等形式开头，不允许出现没有语言标签的裸 ` ``` `
- **行内代码必须用反引号包裹**：正文中出现的函数名、变量名、模块名、参数名等代码片段（如 `chunk_gated_delta_rule`、`cu_seq_lens_q`）用单个反引号 `` `code` `` 包裹，不允许裸写出现在正文中

### 3. `/ai` 标记：请求 AI 补全

用户在笔记中使用 `/ai` 标记来表示「此处需要 AI agent 帮助补全」。`/ai` 之后紧跟着用户对补全内容的具体要求，要求结束后可能接续正文。例如：

```
一些正文内容。/ai 补充 STS 的算法流程，需要对 ECE 指标进行简要描述。后面是继续的正文。
```

AI agent 需要：

1. **识别边界**：判断 `/ai` 后的要求到哪里结束、哪里之后是正文（通常要求是一到两句话的指令，正文是笔记的继续叙述）
2. **补全内容**：根据要求进行笔记补充，遵守上述所有规则（保留原文、中文叙述、标点硬性规则等）
3. **移除标记与要求**：补全完成后，删除 `/ai` 标记及其后的要求文本，仅保留补充的内容（原文中 `/ai` 之前的部分保留不动）
4. **回复确认**：完成补全后回复「完成 /ai xxx 要求」，其中 xxx 是对要求的简短概括

### 4. 笔记风格对齐用户

补全或整理笔记时，**语言风格必须与用户已有笔记保持一致**：

- 用尽可能简洁、清楚的语言进行介绍，避免冗长啰嗦
- 不做过度展开——写到能说清问题为止，不要延伸无关背景或边缘细节
- 术语使用、段落节奏、详略程度均以用户已有笔记为参照

### 5. 标点（硬性规则）

代码块之外的中文正文**必须**使用全角标点：逗号「，」、冒号「：」、分号「；」、括号「（）」、引号「“”」。中文正文中出现半角标点即视为错误，必须先修正再写入。代码块内部与行内代码引用（`code`）内保持英文标点，不受此限。

### 6. Math block 使用 Typora 格式

非 inline math（display math / math block）必须使用 Typora 风格：`$$` 独占一行，公式内容在中间行。

```
# ✓ 好的 — Typora-style math block
$$
c_k = \sigma(w^\top [h_k;\, W_1[x_{k-1}]])
$$

# ✗ 禁止 — 同行的 $$xx$$ 格式
$$c_k = \sigma(w^\top [h_k;\, W_1[x_{k-1}]])$$
```

inline math（行内公式）仍使用单 `$` 包裹：`$\gamma$`、`$T_{\text{draft}} \propto \gamma$`。

### 7. 参考来源：上下文之外还需参考 draft.md

补全笔记（如整理写入 context.md）时，除对话上下文外，还需参考项目根目录的 draft.md：其中包含已经讨论好的实现计划与过程草稿，必要时需要将这些内容整理到 context.md 中。
